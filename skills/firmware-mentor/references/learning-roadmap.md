## 评估原则

- 以“能否在真实约束下独立完成并解释”为标准，不以工龄、背过的名词或看过的课程数量判断。
- 区分知识听懂、能够照做、能够独立设计、能够排障优化、能够指导他人。
- 证据优先：代码、设计说明、测试、故障复盘、性能数据和项目结果。
- 信息不足时给出暂定判断，并提出少量能区分阶段的问题。
- 指出下一阶段的关键缺口，同时明确哪些内容目前可以暂缓。

## 能力阶段

### 入门

能读懂基本项目、完成聚焦修改、按手册配置简单外设、用日志定位基础问题、写简单 Python 辅助脚本。常见缺口是边界/错误处理、CPU/内存模型和独立验证。

### 独立开发

能独立负责模块，设计接口和状态机，处理异常边界，定位中断/内存/并发问题，编写自动化测试并完成模块级验证。评估重点是能否闭环，而非是否“写过驱动”。

### 进阶

能解决跨硬件/固件/系统问题，进行性能、功耗和可靠性优化，参与 Bring-up，设计固件子系统并推动复杂问题闭环。需要展示跨层证据和权衡能力。

### 高级或架构

能负责平台/子系统、做架构和选型、评估性能/资源/安全/维护成本、协调多团队并制定长期技术方案。重点是规模化复用、风险控制和团队影响。

评估输出包含：暂定阶段、已有证据、关键缺口、下一阶段重点、暂缓项和验证项目。

## T 型能力

横向基础保持“够用且能协作”：

- 芯片/硬件基础，C/Python，裸机/RTOS，驱动/协议。
- 编译链接、Linux 基础、测试自动化、工程质量。
- 固件安全、功耗性能、可靠性和量产意识。

纵向只选一条主线形成深度：BSP/Bootloader、Linux 驱动、Bring-up、固件验证、Embedded Linux、固件安全或系统性能。选择依据是当前工作机会、兴趣、可获得硬件/导师和目标岗位，而非热门程度。

## 路线制定流程

1. **定义目标**：日常问题、半年内职责或目标岗位；目标必须可观察。
2. **盘点现状**：列出做过的任务和证据，不让用户先做漫长自测。
3. **找最短缺口**：识别会阻碍当前工作的 1～3 个能力，而非列全部知识。
4. **选择主线**：确定一条纵深方向；其他领域只补接口知识。
5. **设计项目**：每个主题配一个可完成、可演示、可测试的小项目。
6. **嵌入工作**：把日志、测试、手册阅读、复盘或工具脚本应用到现有工作。
7. **设里程碑**：用交付物和能力行为，不用“学完某书”作为完成标准。
8. **定期复盘**：每 4～6 周比较证据、调整难度和删除低价值内容。

## 时间分层

### 当前必须掌握

直接影响安全工作和故障排查：项目构建/调试、C 内存与未定义行为、芯片启动基础、常用外设、中断/并发、超时错误处理、日志和手册阅读。

### 未来 3～6 个月

目标是独立负责模块：状态机、DMA、RTOS 通信、链接/Map、系统化排障、模块测试、Python 自动化、代码评审和接口设计。

### 未来 6～12 个月

目标是形成优势：选择 Bootloader/BSP、验证自动化、Linux 驱动、性能/功耗、安全等一条主线，完成一个端到端项目和一次有证据的复杂故障复盘。

### 未来 1～2 年

围绕目标岗位补系统知识：跨层调试、子系统设计、可靠性与量产、协作和技术表达。不要同时深入所有纵向方向。

每阶段计划用表格给出：主题、为何现在学、实践、交付物、工作结合、目标岗位价值和暂缓内容。

## 实践项目阶梯

按现有硬件和岗位选择，不要求全部完成：

| 层级 | 项目 | 关键能力与交付物 |
| --- | --- | --- |
| 基础 | 裸机 UART + 中断环形缓冲 | 驱动、ISR/主循环并发、溢出策略、测试记录 |
| 基础 | Python 串口日志解析/CLI | 协议、异常、日志、单测和可复现依赖 |
| 中级 | DMA 收发 | 所有权、Cache/对齐、超时、波形与吞吐数据 |
| 中级 | FreeRTOS 多任务通信 | 任务/队列/锁、优先级、栈水位和故障注入 |
| 中级 | HardFault 分析工具 | 异常栈帧、ELF/Map、addr2line 和崩溃报告 |
| 中级 | 寄存器代码生成器 | 数据建模、校验、生成测试和可追溯输入 |
| 进阶 | Bootloader + A/B 升级 | 镜像、校验、掉电恢复、回滚和兼容性 |
| 进阶 | Linux 字符/Platform Driver | 内核接口、设备树、中断/并发和用户态测试 |
| 进阶 | 自动化 HIL 平台 | 仪器/设备控制、批量测试、报告和 CI |

## 成果验证

每个项目至少产出：

- 一页设计：目标、约束、模块、接口和关键权衡。
- 可构建代码和明确版本/环境。
- 正常、边界、错误和恢复测试。
- 可复现演示或自动化测试结果。
- 一次故障复盘：现象、假设、证据、根因、修复、回归。
- 三分钟口头说明：为什么这样设计、还有什么风险。

若计划过满，优先删除与当前工作无连接、没有可用实践环境、短期无法验证的主题。
