## 使用方法

用本地图选择与问题相关的知识链路，不要逐项复述。解释时指出当前技术点位于哪一层、依赖哪些上游、影响哪些下游，以及可观察的软硬件边界。

## 系统分层与上下游

可用下列链路定位问题：

`产品需求 → 芯片架构/IP/RTL/验证 → 封装与板卡 → Boot ROM → Bootloader → BSP/HAL → 固件/驱动 → RTOS/Linux → 中间件/协议栈 → 应用/测试/生产工具 → 客户产品`

- 上游硬件：CPU 内核、总线、存储器、时钟、复位、电源域、数字/模拟 IP、FPGA 原型、仿真、Tape-out、封装测试。
- 固件层：启动、寄存器与外设、异常中断、内存、调度、协议、升级、诊断。
- 下游软件：操作系统、驱动模型、中间件、应用、自动化测试、上位机和量产系统。
- 责任边界：使用可重复实验判断“输入是否正确、模块内部状态是否正确、输出是否正确”。用寄存器/Trace/日志看固件，用示波器/逻辑分析仪看引脚和时序，用替换件或最小固件隔离芯片与板卡。

## C 与固件编程

### 语言与布局

- 指针、数组、字符串、结构体、联合体、枚举、函数指针与回调。
- `const`、`static`、`extern`、宏、内联、固定宽度整数、位操作。
- 对齐、填充、大小端、整数提升、转换、溢出和未定义行为。
- 栈、堆、静态区、Flash/RAM 布局及变量生命周期。

### 并发与硬件语义

- `volatile` 约束编译器对访问的优化，适合硬件寄存器或会被异步改变的对象；不保证原子性、顺序屏障、互斥或线程安全。
- 中断与任务共享数据时，分别考虑原子访问、临界区、内存屏障、缓存一致性和所有权。
- 区分可重入、中断安全和线程安全：三者相关但不等价。
- 用状态机、环形缓冲区、队列、链表和内存池表达受限资源下的生命周期。

### 常见缺陷

野/空指针、越界、Use After Free、栈溢出、泄漏、竞态、死锁、未初始化、位运算优先级错误、符号/宽度转换、整数溢出和优化后行为变化。讲解缺陷时说明触发条件、可见现象、检测手段和修复后的回归点。

## Python 与研发效率

将 Python 定位为固件的“自动化和观测层”：

- 设备交互：串口、网络、调试探针、烧录与复位工具。
- 测试验证：pytest、批量设备、压力/故障注入、仪器控制、报告生成。
- 数据处理：日志解析、性能/功耗数据、可视化、崩溃地址符号化。
- 构建发布：镜像打包、头部/CRC/签名处理、配置校验、CI。
- 代码生成：寄存器定义、配置表、协议数据和测试向量。

工程化检查模块边界、类型标注、异常、日志、配置、CLI、单元测试、依赖锁定、跨平台路径和超时。涉及烧录、签名或量产操作时先提供 dry-run、输入校验和可追溯日志。

## 处理器与存储系统

- CPU：取指、译码、执行，通用/特殊寄存器，调用约定、栈帧、特权级和异常入口。
- Cortex-M：微控制器和低中断延迟；Cortex-R：确定性与实时；Cortex-A：MMU、Cache 和丰富 OS。具体行为以架构手册和芯片 TRM 为准。
- 中断系统：中断源、控制器、优先级、屏蔽、嵌套、上下文保存与恢复。
- 内存：SRAM、DRAM、Flash、TCM；理解延迟、易失性、带宽和初始化需求。
- 保护与并发：MPU/MMU、原子操作、内存屏障、多核共享和一致性。
- 基础设施：片上总线、时钟树、复位树和电源域会同时影响“能否访问、何时稳定、功耗多少”。

## 启动、裸机与 RTOS

### 启动链路

`上电/POR → Boot Strap → Boot ROM → 选择介质/校验镜像 → 向量表与初始 SP → Reset Handler → .data 复制/.bss 清零 → 时钟/内存初始化 → C Runtime → main → 驱动/任务`

复杂系统还可能包含 DDR 初始化、二级 Bootloader、U-Boot、TF-A/TF-M、安全启动、A/B 分区和回滚。定位启动失败时先找“最后一个确定完成的阶段”。

### 裸机与 RTOS

- 裸机：Super Loop、中断驱动、状态机和前后台结构；关键是避免阻塞并明确时序。
- RTOS：任务、优先级、抢占/时间片、上下文切换、任务栈、信号量、互斥锁、队列、事件、定时器和临界区。
- 明确区分中断上下文、任务上下文、Linux 内核态和用户态。ISR 应短小，使用允许的 ISR API，把耗时工作延后。
- 分析优先级反转/继承、死锁、活锁、饥饿和最坏响应时间，而不只观察平均运行效果。
- FreeRTOS、Zephyr、ThreadX、RT-Thread 和自研 RTOS 的 API 不可凭经验互换，需查对应版本文档。

## 外设与驱动

基础范围：GPIO、UART、SPI、I²C、Timer、PWM、ADC、DAC、DMA、Watchdog、RTC。按需扩展 CAN、USB、Ethernet、PCIe、SDIO、I3C、MIPI、DDR、NVMe、MCTP、QSPI、eMMC。

统一分析顺序：

1. 物理连接、电平、上下拉、终端和引脚复用。
2. 电源、时钟与复位是否满足依赖顺序。
3. 控制器寄存器初始化和状态机。
4. 轮询、中断或 DMA 数据路径。
5. 驱动缓冲、并发、超时、恢复和协议语义。
6. 用寄存器、日志、波形和对端状态交叉验证。

## Cache、DMA 与一致性

先画四项：生产者、消费者、CPU Cache 中副本、主存中副本。

- CPU 生产、DMA 消费：DMA 启动前通常需要把脏 Cache Line **Clean** 到主存。
- DMA 生产、CPU 消费：CPU 读取前通常需要 **Invalidate** 对应 Cache Line，丢弃旧副本。
- 双向/描述符：按每次所有权切换分别处理，不用一句“做 Cache 操作”概括。
- 同时检查 Cache Line 对齐、范围取整、Non-cacheable 映射、屏障、描述符状态位和多核一致性。
- Clean/Invalidate 的具体 API、是否隐含屏障、是否按地址范围操作，必须核对平台文档。

## 构建、链接与二进制

建立链路：`预处理 → 编译 → 汇编 → 链接 → ELF → BIN/HEX → 烧录/加载`。

- 工具链：GCC/Clang、交叉编译、Make/CMake、Warning、优化、LTO、静态/动态库。
- 链接：Memory、Section、Symbol、Relocation、链接脚本、入口点、`.text/.rodata/.data/.bss`、堆栈。
- 诊断工具：`size` 看段大小，`nm` 看符号，`readelf` 看 ELF，`objdump` 看段和反汇编，Map 看地址归属，`addr2line` 从地址到源码，GDB 看现场。
- 常见问题：重复/未定义符号、段溢出、镜像增大、初始化异常、错误放置、栈/堆不足和优化相关故障。

## 工程质量、可靠性与量产

- 设计：分层、模块接口、状态机、错误码、参数/边界检查、生命周期和可移植性。
- 恢复：所有等待都有超时；明确重试次数、退避、资源释放、降级与复位策略。
- 观测：结构化日志、故障快照、版本/构建信息、诊断计数器和看门狗原因。
- 质量：代码评审、Git、静态分析、单元/集成/HIL 测试、CI/CD 和可复现发布。
- 可靠性：Brown-out、掉电保护、CRC/冗余、Flash 磨损、长期运行、高低温、电源波动和并发压力。
- 安全：安全启动、签名/Hash、加密与密钥管理、TrustZone、TF-M/TF-A、调试口保护、OTA、A/B 与回滚。
- 量产：烧录、校准、序列号、配置保护、版本追踪、量产测试和现场诊断。

比较“初学者写法”和“成熟工程写法”时，同时说明收益、成本和适用场景，避免无条件引入框架。
