## 先建立运行上下文

优先从仓库、构建文件和用户材料发现以下信息；只有无法发现且会改变结论时再询问：

- 芯片型号、CPU 架构、开发板/板级版本。
- 裸机、RTOS、Bootloader、Linux 内核态或用户态。
- 编译器、版本、优化选项、链接脚本、SDK/HAL 和 RTOS 版本。
- 模块职责、调用者、ISR/任务上下文、硬件外设与时钟/复位依赖。
- 现象、日志、寄存器值、波形、复现条件和期望行为。

先声明哪些是从材料确认的，哪些是合理假设。

## 代码分析顺序

1. **职责和接口**：输入、输出、状态、所有权、生命周期、线程/中断上下文。
2. **正常路径**：沿控制流和数据流理解初始化、运行、停止和恢复。
3. **硬件依赖**：电源、时钟、复位、Pinmux、寄存器、DMA、Cache 和时序。
4. **内存安全**：长度、边界、指针、对齐、栈、堆、释放和整数计算。
5. **并发安全**：共享对象、原子性、锁、临界区、ISR API、屏障和所有权切换。
6. **错误处理**：参数校验、返回值、超时、重试、资源清理、降级和故障恢复。
7. **编译器语义**：`volatile`、别名、未定义行为、优化、内联、链接可见性和警告。
8. **工程属性**：可读、可测试、可移植、兼容、资源和最坏执行时间。
9. **验证**：为每项实质修改设计能失败也能通过的测试或观测点。

审阅时按严重度排序，指出具体触发条件和影响。不要把个人风格偏好写成缺陷。

## 安全修改规则

- 保持改动聚焦并遵循现有风格；不做无关重构。
- 不引入没有必要的依赖、动态分配、长临界区或不可预测阻塞。
- 保留现有 API/ABI 和硬件兼容性，除非用户明确授权破坏性变更。
- 对每个资源获取设计对应释放路径，对每个等待设计超时。
- 对 ISR、锁、Cache、DMA 和寄存器写序列保留必要顺序；根据平台使用正确的屏障/API。
- 不使用猜测的寄存器地址或位掩码。缺少定义时使用诸如 `DEVICE_STATUS_READY_Msk` 的符号名，并标明“请以手册为准”。
- 修改后解释：改了什么、原问题为何发生、修复为何有效、有什么副作用、如何测试。

## 手册阅读方法

不要从寄存器表孤立抄值。按以下顺序建立系统模型：

1. 芯片/外设框图：模块与总线、DMA、中断、时钟、复位的连接。
2. 电源、时钟、复位章节：访问前提、稳定时间和复位状态。
3. 内存映射：地址空间、别名、缓存/共享属性和访问宽度。
4. 外设功能与状态机：工作模式、数据路径和状态转换。
5. 初始化/关闭步骤：顺序、等待条件、超时和禁止操作。
6. 寄存器表：字段语义、复位值、权限、保留位和副作用。
7. 中断/DMA：触发源、使能、清除、优先级和握手。
8. 时序图与电气参数：软件等待无法替代的硬件约束。
9. Errata：受影响版本、触发条件、规避方案和性能代价。
10. 官方示例：用于验证理解，不盲目复制跨版本代码。

## 寄存器语义

| 属性 | 含义与常见风险 |
| --- | --- |
| RO/RW/WO | 只读/读写/只写；WO 读回值通常不可作为真实状态 |
| W1C | 写 1 清除对应位；读改写可能意外清掉其他已置位状态 |
| W0C | 写 0 清除；必须严格按手册构造写值 |
| Read-to-clear | 读取本身有副作用；调试器自动刷新也可能改变现场 |
| Self-clearing | 硬件完成动作后自动清零；轮询必须有超时 |
| Reserved | 通常保持复位值或按手册要求写入，不自行赋值 |
| Reset Value | 区分 POR、系统复位、外设复位和电源域复位后的值 |

还需检查访问宽度、对齐、端序、原子 set/clear 寄存器、锁/解锁序列、写后延迟、posted write、状态同步和跨时钟域限制。

## 代码与手册对照

建立一张最小对照表：

| 代码动作 | 手册依据 | 前置条件 | 预期状态/波形 | 超时/错误路径 |
| --- | --- | --- | --- | --- |
| 使能时钟 | 时钟章节/字段 | 电源域已开启 | 时钟有效状态 | 超时并记录状态 |
| 释放复位 | 复位章节/时序 | 时钟稳定 | Reset 状态撤销 | 重新复位或失败返回 |
| 配置模式 | 外设字段 | 模块处于允许配置状态 | 模式读回/状态变化 | 恢复安全默认值 |
| 清中断 | 中断状态语义 | 已保存诊断信息 | 中断线解除 | 检查仍活跃的源 |

若代码顺序与手册不一致，指出具体章节/字段和可观察后果。没有手册内容时只给核对方法，不生成伪引用。

## 输出格式

代码审阅优先给出：

1. 核心结论和最高风险。
2. 已确认环境与假设。
3. 按严重度排列的问题，每项含位置、触发条件、影响和证据。
4. 聚焦的修改或补丁。
5. 修改原因与权衡。
6. 可执行的构建、静态分析、单元/硬件测试和回归方法。

资料阅读优先给出“系统图景 → 关键章节 → 初始化/状态机 → 寄存器语义 → 可验证步骤”，而非逐页摘要。
