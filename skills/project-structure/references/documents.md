# 文档规则与模板

在初始化文档体系、决定文档归属或合并拆分文档时读取。以下模板用于承载已知事实，不要求逐项创建文件或保留空章节。

## 创建条件

| 文件 | 何时创建或更新 | 内容边界 |
| --- | --- | --- |
| `README.md` | 已知用途和可用入口；使用方式变化时更新 | 用途、安装、运行、基本验证；尚不能运行则如实说明 |
| `AGENTS.md` | 能记录实际工作约定与入口 | 项目导航、约束和验证入口 |
| `docs/prd.md` | 已有明确需求 | 目标、范围、功能行为、约束、验收；待确认内容显式标明 |
| `progress/progress.md` | 已开始实际项目工作，需要保留目标、状态和下一步 | 简洁当前概况；实际交接后由 handoff 添加归档行 |
| `docs/design.md` | 有需要长期保存的模块关系、复杂流程或重要实现取舍 | 职责边界、接口交互、状态和异常处理、设计理由 |

优先复用同等职责的已有文档。既有进度文件不在 `progress/` 时，检查其用途和引用；在明确的初始化或整理范围内迁移并更新引用。普通任务只沿用已有入口并指出冲突，不另建竞争的总览或擅自迁移历史。

为明确的读者和问题创建文档。已有任务系统、接口定义、配置可作为权威来源时直接引用，避免手工维护副本。设计说明不逐函数复述实现。

接口、验证、操作指南和设计决策先放在职责对应的已有文档；需独立查阅、独立维护或原文档难以清晰承载时再拆分。用户要求交付或确有复现、追溯用途时保存报告；其他单次计划、进度播报、修改总结和普通测试结果留在对话中。

## PRD 内容参考

```markdown
# 需求说明

## 目标与范围
明确要解决的问题、使用场景和范围边界。

## 功能与约束
说明输入、预期行为、异常情况以及已知限制。

## 验收条件
列出能够观察或验证的完成条件。

## 待确认
仅列出实际未决定的需求；无待确认内容则省略。
```

需求文档不承载逐日进度；复杂实现安排放在按需创建的设计说明。

## 初始进度总览

```markdown
# 项目进度

最后更新：YYYY-MM-DD HH:mm（时区）

## 当前概况
- 目标 / 当前阶段：
- 已完成并验证：
- 已实现未验证 / 进行中：
- 阻塞：无，或具体问题。
- 下一步：具体动作。
```

用实际信息替换模板内容，未知或未验证状态如实写明。当前概况保存总体里程碑，不只复述最近一次对话，不使用无依据的完成百分比。尚无交接文档时不建立空归档表或虚构链接。归档格式和维护由已有 handoff 技能负责，用户显式调用时再加载该技能。

## AGENTS.md 项目约定参考

仅保留对当前项目实际成立的条款，并与已有说明合并：

```markdown
## 目录与工作入口

- 列出实际主要目录的职责；不列逐文件清单。
- 临时内容使用 work/<任务短名>/，默认不进入版本控制；仅清理确认属于本次任务且无须保留的内容。
- 接续任务时，如 progress/progress.md 存在，先读取当前概况并核对相关工作区；缺少具体信息时才搜索归档索引、读取相关 handoff。
- 实质进度变化时更新已有当前概况。详细交接由用户手动调用 handoff 生成，保留其手动调用约定。
- 修改需求行为时读取相应需求说明；涉及模块协作或重要设计取舍时读取相应设计说明。
```

将泛化入口替换为本项目真实路径；缺少目标文档时省略对应链接。不要把模板提示语写入项目文件。
