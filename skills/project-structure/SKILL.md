# 项目结构管理

让文件归属清晰、文档有明确用途，并让后续 agent 按需读取。跨项目使用；语言、框架和工具的既有约定优先。

## 触发与范围

- 自动介入项目初始化、脚手架规划、需要组织决策的文件新增或移动，以及用户明确要求的目录或文档整理。
- 普通阅读、解释、代码审查和现有文件内容修改不单独触发；执行中出现需要决定文件归属的操作时再介入。
- 用户已指定完整路径的单文件创建不单独触发；若同时存在其他组织决策，则处理这些决策并遵守指定位置。
- 普通任务只规范本次涉及的结构。整体重组既有项目需有对应的整理任务；范围外问题可简短指出。
- 本技能不自动调用 handoff。详细交接归档继续由用户手动调用的 handoff 技能负责。

## 1. 定位并按需读取

确定当前任务的项目根目录，读取适用的 AGENTS.md 和现有入口。已有 `progress/progress.md` 时先读取当前概况，并核对相关工作区状态；只有信息不足时才搜索归档索引、打开相关 handoff。

先看相关路径和文件名，再限定目录、文件类型或关键词搜索，最后读必要内容。相关范围不足时逐步扩大；构建产物、依赖、缓存、临时内容和大数据默认排除，调查需要时再进入。大文件按片段读取，日志先筛选。

完成条件：已识别当前任务适用的目录约定、相关入口与必要的组织决策，无需扫描整个仓库。

## 2. 决定文件归属

新增之前确认用途、是否需要持久保存、是否已有同等职责的位置。优先更新已有权威文件、复用已有目录；仅按实际需要创建。

缺省职责如下，项目已有等价位置时直接复用：

| 位置 | 职责 |
| --- | --- |
| `README.md` | 给人的使用入口 |
| `AGENTS.md` | 本项目的 agent 工作约定和必要导航 |
| `src/` | 正式实现 |
| `tests/` | 测试及测试资源 |
| `docs/` | 需求、设计和需要维护的说明 |
| `scripts/` | 可复用的开发和维护工具 |
| `assets/` | 项目使用的静态资源 |
| `work/<任务短名>/` | 试验、过程日志和中间文件 |
| `outputs/` | 供人取用的最终报告、导出数据等交付物 |
| `progress/` | 持久的进度总览及对话交接归档 |

根目录保留项目入口、项目级配置和主要职责目录。构建产物、依赖、缓存按工具约定存放，`outputs/` 不收纳所有生成文件。

优先采用现有命名风格；没有约定时使用简短、有意义的英文小写名称，多词用连字符。语言、框架和工具要求的名称例外。日期和版本号仅用于真实快照或版本，不以 `temp2`、`new`、`final-final` 等模糊名称累积副本。

新增目录必须对应职责、模块或独立维护边界。不设统一层数或文件数上限，也不创建没有分类价值的单文件多层嵌套。

## 3. 文档与项目导航

初始化文档体系、合并拆分文档或需要创建文档时，读取 [文档规则与模板](references/documents.md)，仅使用当前分支需要的内容。

初始化或建立缺失约定时，在项目根 AGENTS.md 写入简短的实际目录职责、必要入口、临时内容位置和清理边界。已有条款原位更新，保留无关规则。普通新增文件仅在职责或入口变化时更新导航。

项目 AGENTS.md 不复制本技能全文、不维护逐文件目录树。子目录只有独立规则时才增加 AGENTS.md，记录差异即可。文档入口说明何时读取。

进度读取规则应明确：接续工作先读 `progress/progress.md` 的当前概况并核对工作区；历史 handoff 按需读取。已有相同规则时复用。

## 4. 临时内容与进度

临时内容集中到 `work/<任务短名>/`，通过项目采用的忽略机制默认排除版本控制。任务名冲突时增加有意义的区分信息，保留已有忽略配置。

完成可验证阶段、出现阻塞或方向变化时，原位更新已有进度总览中的当前概况；区分已验证、已实现未验证和进行中，写明下一步具体动作。无需每条命令都更新。

当前概况尽量不超过 10 个简短行。总览已有历史归档时，保留全部历史行，仅编辑相关片段；历史变长后使用搜索和有界读取。详细归档的生成、命名、对话条目及链接维护属于 handoff 的职责，本技能不另建交接文件或复制归档流程。

## 5. 收尾

逐项检查本次新增和移动的文件：用途明确、归属正确、没有无用副本或空目录，相关引用和必要导航已更新。

将可复用的试验脚本整理到正式工具位置，将交付结果整理到交付位置。仅清理确认由本次任务生成且已无用途的临时内容；删除前核对解析后的目标路径与归属。归属不明、其他任务的内容和仍需追溯的证据保留，说明保留原因。`progress/` 不属于临时清理范围。

最终回复简述实际改动、交付位置、必要验证和保留的临时内容。默认不另写计划、修改总结、检查报告或收尾文档。
